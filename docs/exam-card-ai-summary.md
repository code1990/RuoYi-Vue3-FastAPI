# 备考卡 `ai_summary` 字段规范

## 目的与边界

`exam_card.ai_summary` 是卡片背面的 **1 分钟面试口述版总结**。它帮助学习者在看完题目后按固定结构回忆并组织答案；不是参考答案的全文副本，也不用于自动判定复习评级。

AI 只能生成候选内容。用户审核、编辑并确认后才能作为正式卡片内容；AI 不得自动覆盖 `answer`、`key_points`，不得改变卡片状态或提交 Again、Hard、Good、Easy 评级。

## 内容要求

- 使用正常中文语速时约 1 分钟：120–220 个汉字；复杂题最多 300 字。
- 固定顺序为「结论 → 2–4 个要点 → 场景、代价或易错点」。
- 一句话结论先回答题目，关键点用 `1）`、`2）` 等短句串联，最后补充一个实际边界。
- 保留必要的技术术语、复杂度、前提条件和版本差异；不要堆砌定义、重复题目或复述长答案。
- 来源信息不完整、过时或相互矛盾时，明确写出“待核对”，不补造事实。
- 输出使用简洁、可直接口述的中文；不使用 Markdown 标题、寒暄或“作为 AI”。

## 与相邻字段的分工

| 字段 | 用途 |
| --- | --- |
| `answer` | 可核对的完整参考答案。 |
| `key_points` | 评分与查漏用的关键得分点清单。 |
| `ai_summary` | 1 分钟连贯口述答案，帮助快速回忆。 |

## 输出模板

```text
结论：<一句话直接回答题目>。
要点：1）<关键点>；2）<关键点>；3）<关键点>。
补充：<适用场景、代价、易错点或待核对信息>。
```

## 示例

题目：什么是 MyBatis？

```text
结论：MyBatis 是保留 SQL 控制能力的半 ORM 框架，适合复杂查询和性能敏感场景。
要点：1）封装 JDBC 的连接、参数和结果集处理；2）通过 XML 或注解映射 SQL；3）动态 SQL 能适应多条件查询。
补充：优点是灵活可控，代价是复杂 SQL 的编写和维护成本更高。
```

## 验收

- 朗读通常可在 1 分钟内完成，且不超过 300 个汉字。
- 学习者只看题面后，能借此复述结论、关键点和一个边界。
- 内容与 `answer`、`key_points` 一致；无法确认的内容已标识，不存在虚构事实。
- 人工可修改、清空或拒绝 AI 候选总结，不影响既有答案和复习记录。
